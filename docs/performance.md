# 短连接性能实测（历史复用模式）

当前模型流式首段与 SSH 大流量对比见 [新的测试报告](streaming-performance.md)。

当前默认已改为独立 HTTPS 连接。本文的“新版”指当时的复用实现，不是现在的默认模式；此处数据未重新测量。

测试日期：2026-10-31。目标是减少短连接建立成本，同时保留 TLS 加密、证书验证和标准 HTTPS 传输。

## 条件与方法

- Linux 本机回环，Intel Core Ultra 9 185H。
- 两版均为 Rust release 构建；客户端、服务端各 4 个 Tokio 工作线程。
- 旧版：每个 TCP 业务连接另建 TLS 数据隧道，保留其默认 TLS 会话恢复行为。
- 新版：4 条预热的 HTTP/2/TLS 连接，业务连接使用独立 HTTP/2 流。
- 每个样本新建公网侧 TCP 连接，发送 1 KiB，等待完整 1 KiB 回显；延迟包含 TCP 建连和完整响应。
- 串行与 32 并发分别每轮 1,000 个请求，预热 64 次，不计入样本；每组执行 3 轮。
- Python asyncio 负载发生器和回显服务；直连回显作为同机对照。
- CPU 时间是 srv 与 clnt 的用户态及内核态合计，不含 Python；Linux 计时分辨率限制小样本精度。

旧版来自改造前的工作区快照，两版可执行文件 SHA-256 及每轮原始结果分别保存在 [before.json](benchmarks/before.json) 与 [after.json](benchmarks/after.json)。最终新版基准没有同时运行编译或端到端测试。

## 结果

以下是三个独立轮次各项指标的中位数，**不是将全部样本合并计算的分位数**。

| 并发 | 指标 | 旧版逐连接 TLS | 新版 HTTPS 连接池 |
| --- | --- | ---: | ---: |
| 1 | p50 完整响应延迟 | 0.411 ms | 0.341 ms |
| 1 | p95 完整响应延迟 | 1.157 ms | 0.441 ms |
| 1 | p99 完整响应延迟 | 1.467 ms | 0.521 ms |
| 1 | 完成请求/秒 | 1,633.5 | 2,709.2 |
| 1 | 每 1,000 请求代理 CPU 时间 | 0.62 s | 0.30 s |
| 32 | p50 完整响应延迟 | 3.193 ms | 2.607 ms |
| 32 | p95 完整响应延迟 | 5.047 ms | 3.080 ms |
| 32 | p99 完整响应延迟 | 6.662 ms | 3.294 ms |
| 32 | 完成请求/秒 | 8,295.4 | 9,901.3 |
| 32 | 每 1,000 请求代理 CPU 时间 | 0.67 s | 0.20 s |

在这个负载下，串行 p95 下降约 62%，32 并发 p95 下降约 39%，32 并发代理 CPU 时间下降约 70%。32 并发新版单轮 p99 在 3.100–15.569 ms 之间，尾延迟存在明显波动，不能用中位数承诺延迟上界。

新版同期直连对照的 p50 中位数为串行 0.142 ms、32 并发 2.225 ms。负载发生器、内核调度和同机资源竞争也参与结果，因此报告中的完成率不是 RVNX 的最大连接处理能力。

## TLS 的实际影响

TLS 成本包含握手、持续加解密及记录处理。此次优化主要消除了业务连接上重复发生的 TLS 握手；HTTP/2 分帧、转发、认证和加密仍有成本。两版都启用 TLS，结果证明在保留加密时也可以降低短连接成本，不能由此分离计算出“TLS 单独慢了百分之多少”。

上线前应在目标 CPU 和真实 RTT 下复测，并加入长时间负载、更多并发、丢包、冷启动、连接池恢复和多客户端条件。HTTP/2 复用仍受底层 TCP 丢包影响；多连接池分散影响，不能消除 TCP 队头阻塞。

## 复现当前版本

```sh
cargo build --release --workspace
python3 tests/bench_short.py --multiplex --samples 1000 --concurrency 1 32 --repeats 3 --output /tmp/rvnx-bench.json
```

当前脚本默认测独立模式，添加 `--multiplex` 测复用模式，并在 JSON 中记录该开关。通过 `--bin-dir` 可指定支持 `multiplex` 配置的其他版本；更早版本需使用其当时的基准脚本。默认测量 1 KiB 请求，可用 `--bytes` 调整大小。应串行执行不同版本的基准，并在运行期间停止编译和其他压测。

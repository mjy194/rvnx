更新：2026-11-01。本轮新增 **21 项单元测试、2 项端到端测试**，并补强既有用例的错误传播和日志断言。当前 **92 项单元测试、30 项端到端测试全部通过**，包含 65 秒模型首段等待；无失败、无跳过、无强制结束测试进程。格式检查、全工作区全部目标的 Clippy 检查通过，警告视为错误。

合并代码区域覆盖率 **94.34%（3234/3428）**，函数覆盖率 **100.00%（223/223）**。本轮没有开启分支覆盖统计，代码区域覆盖率不等于分支覆盖率。

相比上一轮，单元行覆盖率由 **72.82% 提高到 79.32%**，合并行覆盖率由 **97.24% 提高到 97.95%**。抽取私有会话、数据报和连接池清理接口后，可统计行数从 1957 变为 2002；这些接口采用静态分派。

机器可读结果见 [覆盖率摘要](coverage/summary.json)，包含每文件统计、生产源码 SHA-256 和本次端到端二进制哈希；执行记录见 [测试结果](coverage/test-results.txt)。逐行 HTML 位于 `target/coverage/unit/html/index.html` 和 `target/coverage/combined/html/index.html`，不纳入版本管理。

完整端到端运行耗时 **117.500 秒**。最后补强了一条单元测试的“后续写入继续返回 WriteZero”断言，随后重跑全部单元测试并重新收集覆盖率；合并前核对生产源码、端到端测试文件和客户端/服务端二进制哈希全部一致，复用了本次已通过的 30 项端到端原始记录。本次合并没有 LLVM 哈希不匹配警告，见 [诊断记录](coverage/llvm-diagnostics.txt)。

## 本轮补齐的验证

| 范围 | 验证内容 |
| --- | --- |
| 客户端会话 | TCP/UDP 会话拒绝非预期帧；退出时取消仍活动的传输；传输任务 panic 会结束会话并释放其他子任务；单次 TCP 失败只取消自己的票据，控制通道继续响应；UDP 子任务失败后可重建同一个 peer。 |
| 服务端 UDP | 注入一次 `send_to` 错误，确认只丢弃该包并记录错误，随后正常响应；忽略未知 peer；IPv6 超长包不分配 peer；达到 peer 容量后拒绝新访客，已有访客仍可用。 |
| 客户端 UDP | IPv6 超长响应被丢弃，后续正常响应继续转发；原有 IPv4/IPv6 往返、队列背压、队列关闭、内核发送错误测试保留。 |
| 连接池与 CF | 迟到的失效连接清理不能删除已替换的新连接；CF 预热不等待测速或建立普通池；认证失败的候选在消耗下载预算前被淘汰；慢候选提前停止的日志及流量计数同时验证。 |
| gRPC / 帧协议 | gRPC 首部或正文部分读取后取消可继续解码；部分刷新取消后不丢失已排队数据或下一条消息；首部和正文底层读取错误保留错误类型；排队数据失败会在后续写入中返回错误；控制帧、数据报各字段截断返回 EOF；写完帧后刷新失败仍返回错误。 |
| HTTPS 测速 | 成功响应头不能替代必须存在的成功 trailers；构造器拒绝越界池大小和非法认证头；非法、超长、附带额外内容的测速请求失败后释放测速并发名额，同一连接可继续正常测速。 |
| TLS 与启动 | 空、非法 PEM、非法 DER 和缺失证书文件被拒绝；连接被拒绝、TLS 名称非法和握手停滞有明确错误或超时；两端启动时拒绝缺失配置、弱令牌、错误 TLS 文件；服务端监听端口占用会退出，已有服务继续工作。 |
| 日志与资源释放 | 真实子进程验证 `RUST_LOG` 缺失或非法时回退到默认日志；线程局部日志捕获验证 UDP 故障和慢候选日志；写任务测试等待 JoinHandle 的结果，避免遗漏后台 panic。 |

已有主备测试继续覆盖冷启动、稳定主备、连续低速与恢复清零、保活故障、迟到健康结果、成功立即补备与失败退避、并发软硬预算、排队超时、取消、旧流保留、候选回退、流量预算，以及配置边界。真实进程回归继续覆盖 TCP/UDP、独立 TLS、复用、证书与认证、半关闭、慢流隔离、模型流式输出、HTTP Keep-Alive、连接轮换、容量恢复和正常退出。

测试使用暂停时钟、真实内存 HTTP/2 协议栈和可控错误注入；网络测试仅使用本地回环端口。客户端传输和服务端 UDP 的私有接口用于注入失败，不引入动态分派。日志捕获仅作用于当前测试线程，不修改进程环境中的 `RUST_LOG`。

## 剩余统计记录的具体含义

LLVM 汇总仍有 **41 行未覆盖**，不应把它解释为同样数量的未测业务场景。隐藏泛型实例的合并逐行视图中，仅剩 **10 个显示为零次的源位置**：9 个是错误返回或作用域结束位置，另一个是 HTTP/2 容量回调的防御分支。逐项位置及原文见 [未覆盖位置清单](coverage/uncovered-lines.json)。该清单与 LLVM 汇总采用不同的展示口径，没有替换上表的分母。

已核对 `Cargo.lock` 锁定的 **h2 0.4.13** 源码：`src/proto/streams/send.rs` 的 `poll_capacity` 实现只有 `Pending`、`Ready(None)` 和 `Ready(Some(Ok(...)))`；当前实现不会生成 `Some(Err(...))`。RVNX 保留该错误处理以兼容 API 的完整返回类型，没有为追求数字删除防御代码或排除统计。

其他尚未执行的代码区域还包括配置预校验后的防御式返回、特定 OS/I/O 错误及宏/泛型的覆盖映射。函数覆盖 100% 不代表所有分支或所有线程交错已被穷举。本轮未使用 Loom 穷举，也未连接真实 Cloudflare 公网节点。插桩测试耗时不作为性能基准。

## 已保留的退出回归修复

服务端退出 future 固定在监听循环外，避免反复创建 `ctrl_c()` 订阅时漏掉退出信号。端到端测试要求进程正常退出；超时强制结束和异常退出均判为失败，并继续回收其他测试资源。持有 HTTP/1 长连接和 TCP 业务的退出场景包含在完整回归中。

CF 补备子任务 panic 的测试验证当前停止策略及资源释放，不承诺 panic 后自动重启调度器。普通网络失败继续验证既有退避与恢复流程。

## 复现

在仓库根目录执行：

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --workspace --locked
python3 -m pip install -r tests/requirements.txt
RVNX_LONG_TESTS=1 python3 tests/e2e.py
```

CI 已启用 `RVNX_LONG_TESTS=1`；省略该变量会跳过 65 秒模型等待。单元测试和端到端测试均需要本机 IPv4/IPv6 回环端口权限。

```sh
rustup component add llvm-tools-preview
python3 scripts/coverage.py
```

覆盖率脚本使用锁定依赖和离线构建，因此首次运行前需先完成依赖下载；还需 OpenSSL 和上述 Python 依赖。默认完整运行单元和端到端测试，分别输出两种口径。插桩构建缓存位于系统临时目录，可用 `RVNX_COVERAGE_BUILD_DIR` 覆盖。

`python3 scripts/coverage.py --unit-only` 仅重测单元覆盖率，并移除旧的合并报告。每次完整运行后可用 `target/coverage/summary.json` 更新本报告及 `docs/coverage/summary.json`。
